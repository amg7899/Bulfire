# BULFIRE website

Static site (plain HTML + CSS + a little JS, no build step) for BULFIRE Ltd., replacing the old WordPress site at https://bulfire.ecoes.eu/. A sister of ecoes.eu (repo amg7899/SUM, its CLAUDE.md has the full history of the shared design decisions) and franchise.ecoes.eu (repo amg7899/FranchiseEcoes). Started 2026-11-26 at the client's request ("modernise it like the previous 2 sites").

## Publishing
- GitHub Pages from the branch `claude/festive-ride-jemver` (root), switched on by the client 2026-11-26 (Settings → Pages; no tool here can change it). Preview: https://amg7899.github.io/Bulfire/ (push → live in about a minute; the sandbox cannot open github.io, so check the "pages build and deployment" run in the repository's Actions instead).
- All paths are relative, so the site works at the preview address and on the domain.
- Go-live steps sent to the client 2026-11-27 (with a ready e-mail to SuperHosting in Bulgarian and English). When the client adds the custom domain in Settings → Pages, GitHub commits a `CNAME` file to the branch: fetch and merge it before the next push (`git fetch origin claude/festive-ride-jemver && git merge --no-edit FETCH_HEAD`). From that moment the preview address redirects to bulfire.ecoes.eu, which shows the old WordPress until SuperHosting changes the DNS.
- Go-live (when the client approves the new site): add a `CNAME` file with `bulfire.ecoes.eu` (or set the custom domain in Settings → Pages, which writes it), and the client asks SuperHosting (registrar/DNS of ecoes.eu, see SUM's CLAUDE.md) for one record: `bulfire` CNAME → `amg7899.github.io` (replacing its current A record). Not before: a CNAME file would send the preview to the old WordPress. E-mail is not affected (addresses are @ecoes.eu). Then Enforce HTTPS. The ecoes.eu footers already link to bulfire.ecoes.eu.
- The old site: WordPress (theme Woodmart, WPBakery, WooCommerce, GTranslate dropdown) at SuperHosting. Reachable from this environment since 2026-11-26 (bulfire.ecoes.eu added to the environment's allowed hosts). SuperHosting's bot check ("Please wait while your request is being verified") blocks repeated page loads in a browser; the REST API works: `wp-json/wp/v2/pages?per_page=100`, `wp-json/wp/v2/media/<id>`, `wp-json/wc/store/v1/products?per_page=100&page=N`, images from `wp-content/uploads/…`. Page content is WPBakery shortcodes with curly quotes (`vc_single_image image=“862″` → media id).
